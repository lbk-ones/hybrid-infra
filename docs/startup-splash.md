# 启动屏与加载动画

默认开启独立的居中启动屏，使用项目品牌图标、旋转细环、呼吸光晕和流动加载条。主窗口在后台加载；启动屏按真实阶段显示「正在准备桌面环境」「正在加载工作空间」「一切就绪，即将进入」。加载条是不定进度动画，不模拟下载百分比，支持系统减少动态效果偏好。

## 配置开关

在实际使用的配置文件中增加或修改：

```json
{
  "splashEnabled": true
}
```

- `true`：显示启动屏，主页面就绪后自动交接并关闭启动屏。
- `false`：不创建启动屏窗口，主窗口直接显示；首次本地引导静默完成，加载失败仍显示完整错误恢复页。
- 未填写时默认为 `true`。修改后重启生效。

可通过「桌面能力 → 偏好与启动设置 → 启动配置」保存完整 JSON，或直接编辑 `HYBRID_SETTINGS` 指定的配置文件。参考 `settings.example.json`。本次不覆盖根目录实际 `settings.json`。

## 交接和恢复

启动屏的 WebView 就绪后才显示，最短展示 600 毫秒，避免快速加载时瞬间闪烁；完成后有 180 毫秒淡出。主页面由既有的 `Host.Ready()` 或宿主注入的原生就绪消息确认，不依靠前端动画或假进度判断。

业务页面加载失败或达到原有 `loadTimeoutSeconds` 限制时，启动屏同样结束，主窗口显示可重试、可返回首页的错误页。启动屏本身的 WebView 若在应用启动后 4 秒仍未就绪，会强制展示主窗口，避免应用一直隐藏。这 4 秒只约束启动屏自身，不限制业务页面的正常加载时间。

启动屏右上角按钮、Escape 或 Alt+F4 可以跳过启动屏并显示主窗口。托盘唤醒或第二实例转交也会跳过启动屏。启动屏不记忆尺寸、不重复展示；后台下载等任务仍沿用原来的退出保护。所有计时器在退出时停止，防止退出期间重新弹出窗口。

启动屏是内部窗口，只继承 `host` 能力。`Host.GetStartupState()` 和 `Host.DismissSplash()` 还会校验真实调用窗口名，普通业务页面不能通过这些接口操控启动屏或读取启动元数据。原有来源权限、窗口恢复和更新健康确认机制保持原来的职责。

## 实现与验证

- Go：`go/host/splash.go`，接入主窗口就绪、加载错误、唤醒和退出生命周期。
- 前端：`frontend/shell/splash.html`、`frontend/src/shell-splash.js`、`frontend/public/splash.css`。
- 单元测试覆盖：默认开启和显式关闭、窗口初始可见性、主页面先就绪、最短展示时间、重复事件、跳过、启动屏超时、退出清理、调用窗口隔离、加载错误交接。
- Windows 原生验收：在独立数据目录中检查了 480×360 动画页面，无滚动条或内容裁切；本机延迟页面加载后主窗口自动显示；加载超时后正常显示 `E_LOAD_TIMEOUT`、重新加载和返回首页入口。
- 启动屏在任务栏隐藏，测试工具未直接捕获独立工具窗口本身；布局通过相同页面的独立原生预览确认。macOS/Linux 原生显示尚未验收。
