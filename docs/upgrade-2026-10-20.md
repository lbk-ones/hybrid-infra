## 修复内容

- 弹框通过 encoding/json 传入对象，不直接拼接引号字符串或模板字符串。DOM 未就绪时延后应用数据。
- Alert/Confirm 标题、正文与按钮按纯文本显示，支持引号、反引号、换行及模板插值字符；Show 保留受信任 HTML 展示能力。
- Confirm 使用 atomic.Add 分配独立事件和窗口名，在展示前订阅；只接收同名来源窗口的有效结果。首个结果胜出，重复、错误类型和其他值不触发异常。
- 关闭、请求取消、应用退出、超时均停止 Confirm 等待；退出时清理事件订阅和窗口。默认超时 300 秒，可配置，上限一天。
- Alert 的 place 参数生效，演示调用补足第四个参数。
- 修正工作区偏移、左上角/右下角定位；窗口和截图分别使用逻辑坐标与物理像素。工作区不可用时子窗口回退居中。
- 删除无法编译的重复 Linux/macOS 平台实现，统一使用 Wails ScreenManager。屏幕查询不再以 log.Fatal 结束进程。
- isFullscreen 对应真正全屏；无效子窗口尺寸回退默认值。主窗口同时配置正数宽高时使用普通窗口尺寸，否则默认最大化。
- Screenshot 返回错误，修正矩形右下角坐标并检查 PNG 写入错误。
- settings 支持显式路径、用户目录、程序同目录和开发配置回退；配置损坏明确报错。KV 使用固定用户目录。
- 主窗口 F12 按 debug 配置启用；时间事件 goroutine 随应用退出停止。
- CORS 使用配置来源与主页面来源，移除通配来源，并包含分块上传所需请求头。此改动不提供服务级授权或不可信网页隔离。
- hybrid 导出改用 Node 文件 API，兼容 Windows，无需 rm/sed/eval；校验三个 Wails 版本，并生成版本及 bindings 哈希清单。
- 导出的 JS 使用相对路径，可复制到任意静态目录；新增 client.js facade、可配置 origin、自定义 transport 接口，原生成 bindings 路径仍可导入。
- 构建检测 `pnpm version` 改为 `pnpm --version`，依赖安装使用 frozen lockfile。pnpm-workspace.yaml 允许 esbuild 构建脚本。

## 兼容变化及迁移

### HTML 弹框

Alert/Confirm 不再解释 HTML。例如 `<span>内容</span>` 将显示为原始文字。需要富文本时用 `UI.Show` 并只传受信任应用 HTML；如果业务要求富文本确认框，应单独实现明确的数据和 HTML 清洗约定，不要恢复脚本拼接。

### KV 数据文件

原工作目录的 store.json 保留不动，新默认文件为用户数据目录的 store.json。迁移前关闭外壳，备份新旧文件，确认目标没有需保留的数据，然后复制旧文件到新目录。不会自动合并或覆盖用户 KV。

Windows PowerShell 示例（最后一行只在目标不存在时复制）：

```powershell
$dataDir = Join-Path $env:APPDATA 'hybrid-infra'
New-Item -ItemType Directory -Force $dataDir | Out-Null
$targetStore = Join-Path $dataDir 'store.json'
if (-not (Test-Path -LiteralPath $targetStore)) {
    Copy-Item -LiteralPath './store.json' -Destination $targetStore
}
```

使用 HYBRID_DATA_DIR 时应迁移到该目录。可用 HYBRID_SETTINGS 指定部署配置，避免启动目录变化。用户配置优先于程序同目录配置。

### 前端与运行时

前端应复制整个新 hybrid 目录，与新外壳一起发布。旧的 `/hybrid/bindings/...` 用法仍可保留目录名继续使用；也可从新的 client.js 导入 UI/Store/Log/Runtime。独立部署的额外来源需加入 allowedOrigins，不再默认允许任意网页跨源请求。

根目录 settings.json 未被本次操作改写；新字段可参考 settings.example.json。关闭 debug 后 F12 不再由主窗口快捷键打开开发者工具。

## 目标平台人工验收清单

### 开发启动问题补充（2026-10-20）

已复现并修复 `wails3 dev` 无窗口的问题：原命令 `pnpm run dev -- --port ... --strictPort` 在 pnpm 11 下将多余的 `--` 传入 Vite，使端口参数失效。Wails 等待 9245，而 Vite 实际使用 5173/5174，宿主无法继续启动。

去掉 `--` 后发现第二个问题：Windows 下 Vite 的 localhost 仅监听 IPv6 `::1`，Wails 的资产代理通过 IPv4 `127.0.0.1` 连接，页面返回 502。因此最终命令为：

```shell
pnpm run dev --host 127.0.0.1 --port {{.VITE_PORT}} --strictPort
```

修复位于 build/Taskfile.yml 的 dev:frontend。验证使用直接 `wails3 dev`：Vite 正确监听 127.0.0.1:9245，宿主连接成功，创建主窗口，并记录真实 WebView 的 Alert 服务调用、Alert.html/runtime.js 200 响应及自动关闭。此项补充了上面首次升级时尚未执行的开发模式启动验收。
